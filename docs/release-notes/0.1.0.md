# DiscDock 0.1.0

DiscDock 0.1.0 is a Linux-first catalog for removable and external media. It records file metadata so users can search a collection without reconnecting every physical device.

## Included

- Manual media registration and Linux removable-device detection
- Metadata-only, quick-hash, and full SHA-256 scans
- Scan progress, cancellation, scan history, errors, and verification reminders
- Global search across disconnected media with media, kind, tag, size, date, scan-status, and verification filters
- Filtered CSV export, JSON/CSV catalog export, full database backup, and validated restore with a pre-restore safety backup
- Duplicate reports, media tags, file annotations, collections, custom media types, and custom fields
- Contextual in-app Help with keyboard access and persisted panel sizing
- Linux `.deb` and `.AppImage` packages

## Data and privacy

DiscDock stores its catalog, settings, logs, covers, and safety backups under Electron's user-data paths. It catalogs metadata and does not copy or back up original file contents.

Core registration, scanning, search, backup, restore, and export work offline. Audio CD title and cover enrichment and automatic update checks are disabled by default and can be enabled in Settings. Optional audio enrichment sends a computed disc ID and track count to MusicBrainz and may request selected cover art from Cover Art Archive.

## Linux prerequisites

Ordinary folder-based cataloging needs no external device utility. Device detection uses `lsblk`; safe removal uses `udisksctl`; optical eject uses `eject`. Audio CD table-of-contents cataloging additionally needs `cd-info` or `cdparanoia`.

## Upgrades and recovery

Database migrations run automatically at startup. Existing databases are copied to a `backups/pre-migration-*.sqlite3` safety file before pending migrations. Restore validates the selected database before replacing the active catalog and creates a `backups/pre-restore-*.sqlite3` safety backup first.

## Known limitations

- Linux is the supported release platform.
- Large full-hash scans still run in the Electron main process and need scale/responsiveness acceptance testing.
- Export and backup show operation status and completion notifications but are not yet cancellable background jobs.
- Clean GUI launch/quit testing for packages requires a headless display environment such as Xvfb.
- ESLint is deferred because the project intentionally retains TypeScript 7 and current TypeScript ESLint releases do not support it.
